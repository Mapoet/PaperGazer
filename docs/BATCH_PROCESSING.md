# 分批处理功能说明

## 概述

`daily_ingest.py` 脚本现在支持自动分批处理长时间跨度的数据抓取任务，以避免单次查询数据量过大（超过 2000 条）导致的问题。

## 自动分批机制

当使用 `--since`、`--until` 或 `--days` 参数指定的时间跨度**大于 3 天**时，脚本会自动：

1. 将时间范围分成多个批次
2. 每批处理 **3 天**的数据
3. 自动合并所有批次的结果
4. 显示每批的处理进度

## 使用示例

### 示例 1: 查询最近 30 天的论文

```bash
python scripts/daily_ingest.py --days 30
```

**输出**:
```
时间跨度为 30 天，将分批处理（每批 3 天）以避免数据量过大

批次 1: 2025-10-12 至 2025-10-15
批次 2: 2025-10-15 至 2025-10-18
批次 3: 2025-10-18 至 2025-10-21
...
批次 10: 2025-11-09 至 2025-11-11

分批处理完成，共 10 批
```

### 示例 2: 查询指定日期范围

```bash
python scripts/daily_ingest.py --since 2025-01-01 --until 2025-01-31
```

这将自动分成约 10 批（每批 3 天），覆盖整个 1 月份。

### 示例 3: 短时间跨度（不分批）

```bash
python scripts/daily_ingest.py --days 2
```

时间跨度 ≤ 3 天时，不会分批，直接一次性处理。

## 技术细节

### 分批大小

- **默认**: 3 天/批
- **位置**: `daily_ingest.py` 第 212 行
- **可调整**: 修改 `batch_size_days` 变量

```python
batch_size_days = 3  # 每批处理 3 天
```

### 结果合并

脚本会自动合并所有批次的结果：

- **论文数量**: 累加所有批次的论文数
- **统计信息**: 合并 Unpaywall 等数据源的详细统计
- **错误处理**: 保留每个数据源的错误信息

### 性能优化

**为什么选择 3 天?**

- arXiv API 单次最多返回 30,000 条，每页最多 2,000 条
- Crossref API 使用游标分页，但长时间跨度可能导致：
  - 游标循环问题
  - 超时问题
- 3 天是一个平衡点：
  - 足够小，避免单次数据量过大
  - 足够大，减少 API 调用次数

## 批次处理流程

```
用户指定时间范围（如 30 天）
  ↓
检测时间跨度 > 3 天
  ↓
计算批次数（30 ÷ 3 = 10 批）
  ↓
批次 1: 处理第 1-3 天 → 结果 1
批次 2: 处理第 4-6 天 → 结果 2
...
批次 10: 处理第 28-30 天 → 结果 10
  ↓
合并所有结果
  ↓
显示统一的汇总表格
```

## 注意事项

1. **检查点影响**: 使用 `--since`/`--until`/`--days` 时会忽略检查点过滤
2. **数据去重**: 数据库的唯一约束会自动去重，重复抓取同一论文不会导致重复记录
3. **时间精度**: 批次边界可能导致某些论文被多次查询，但会被去重
4. **进度显示**: 每批都会显示独立的进度信息

## 配合下载功能

分批处理同样支持下载功能：

```bash
# 查询并下载最近 30 天的论文
python scripts/daily_ingest.py --days 30 --download

# 只下载 OA 论文
python scripts/daily_ingest.py --days 30 --download --download-oa-only
```

下载操作在所有批次完成后统一执行。

## 故障处理

如果某个批次失败：

- 脚本会继续处理后续批次
- 最终结果会包含所有成功批次的数据
- 失败批次的错误信息会在结果表格中显示
